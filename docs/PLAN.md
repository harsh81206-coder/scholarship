# Full-flow implementation plan

Updated: 2026-11-26. This is the route inventory and implementation map for the full-flow blueprint. The checkout currently has **45 `page.tsx` routes** (verified with `find web/app -name page.tsx`), while the blueprint says the source archive had 47. This plan reconciles the requested target of 64 by mapping the 45 checked-in routes, all 17 mandatory additions, and the 2 bonus routes (`/admin/ml`, `/vendor/returns`). The 2-route source-archive difference is not silently counted as existing work.

## Shared schemas and file handling

Existing core tables cover geography, accounts, students/families/banks, academic records, documents, schemes/eligibility, applications/events, cycles/batches/handovers, DBT, grievances/messages, notifications, fraud, audit, delegations, settings, and time series. Add the blueprint tables `budget_allocation`, `vendor_order`, `invoice`, `certificate`, `upload_file`, and optional `defect`; use `academic_record` for monthly attendance unless its current shape proves insufficient. Every write path must add the appropriate `audit_log` row and recipient `notification`, and all uploads must validate MIME/size, hash content, and live under ignored `api/data/uploads/`.

Generate fake, clearly watermarked material with `scripts/gen_samples.py` into `web/public/samples/`: masked-Aadhaar sample, two income/caste/marksheet/bonafide/bank/domicile/disability samples, attendance and marks templates plus good/bad sample imports, cycle and batch QR PNGs, and a sample handover photo. Existing `demo_docs/` are seed OCR examples, not real personal documents. Do not add `.env`, `.env.local`, generated SQLite files, `.next`, `__pycache__`, or `.DS_Store` to distributable ZIPs.

## Implementation order and gates

1. **Inventory and skeletons (P0):** this route map; replace the eight 17-line placeholders; create the 17 mandatory route pages plus the two bonus pages with shared shells, API-backed empty/loading/error states, and working navigation. Add global `not-found.tsx`, `error.tsx`, and `loading.tsx`.
2. **Shared foundations (P0):** QR encode/scan (camera, image and paste), file registry and sample generation, PDF/CSV helpers, public certificate/transparency API, notification triggers, role-safe global search and officer notification bell.
3. **Money flow (P0):** budgets, sanction certificate, DBT receipt PDF, retries, exports and vendor purchase orders/invoices/payments. Ensure every state transition audits, notifies and invalidates relevant queries.
4. **Cycle flow (P0):** signed batch/cycle QR, labels, GPS tracking, receive and handover scans, handover receipt, defect/return path, forecast-driven demand and vendor payout.
5. **Screen data flows (P0/P1):** school reports/grievances/students; TPEO and DEO applications/delegations/schools; student bank/ID/application detail; admin users/settings/schemes/ranking/ML; public help/privacy/transparency.
6. **Demo readiness (P1/P3):** deterministic larger seed and sample files, 12-step demo guide/reset, route- and flow-level Playwright, accessibility/language check, package hygiene and final docs.

After each implementation phase run `cd api && ruff check app tests && pytest -q`, then `cd web && npx tsc --noEmit && npm run lint && npm run build`. Add endpoint-specific and browser tests alongside each new flow. Existing endpoint presence and 33-route screenshots are not evidence that all 64 pages work.
